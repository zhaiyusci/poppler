# Local Fork Notes

This branch contains downstream changes in addition to upstream Poppler. Keep
those changes generic: consumer application names, UI policy, and product data
must not be introduced into this repository.

## Downstream Extension Areas

- FreeText appearance and font fallback behavior, including Windows and CJK
  handling.
- Annotation behavior exposed through the Qt 6 wrapper.
- `utils/PdfPageSequenceEditor.{h,cc}`, a Core API helper for inserting,
  importing, deleting, moving, and reordering PDF pages.
- `utils/PdfAnnotationFlattener.{h,cc}`, a Core API helper for flattening normal
  annotation appearances into a new PDF snapshot without rasterizing pages.
- `utils/pdfpagesequence.cc`, an optional command-line frontend built when
  `ENABLE_UTILS` is enabled.

The page-sequence editor uses Poppler's unstable Core C++ API and does not
define a stable public ABI. Consumers that compile it directly must use source,
generated private headers, and Poppler libraries from compatible revisions.

## Annotation Flattening Helper

`PdfAnnotationFlattener::flatten(inputSnapshot, newOutput)` compiles directly
against the matching Core headers/library, like the page-sequence editor. No
Core ABI or build-system change is required. The caller must first serialize all
live edits into the input snapshot; this helper does not access a UI document.
It never writes the input. Output must not exist, including through a symlink.
After preflight and an in-memory edit, it writes a sibling temporary file,
reopens it to validate page readability, then atomically publishes a hard link
without replacing any existing file. The destination filesystem must support
hard links (for example NTFS); otherwise the operation fails cleanly. Temporary
files are cleaned on ordinary success/failure; process termination may leave a
`.flatten-*.tmp` directory. The caller owns final user-facing save/replace policy.

### Rendering and preservation contract

- This is a **screen-view** flattening operation, not a print-view export.
  Invisible, Hidden and NoView annotations are not painted and remain in the
  annotation array. Link and Widget annotations and the AcroForm graph are kept.
  Thus the result intentionally need not have an empty `/Annots` array. Once
  visible markup becomes page content it also prints, regardless of its former
  Print flag. Widgets/links still render in the viewer's annotation pass above
  ordinary page content. Flattening rejects overlap with an earlier visible
  retained Link/Widget, because moving the markup into Contents would reverse
  that pair's original stacking order. This uses the actual transformed AP bounds,
  including expanded generated appearances. An earlier retained Link/Widget with
  dynamic NoZoom/NoRotate/ToggleNoView bounds is conservatively rejected outright.
- Existing `/AP /N` is authoritative. A state dictionary requires an explicit
  `/AS` selecting a stream; no arbitrary first-state fallback is allowed.
  Four corners of the Form `/BBox` are transformed by its `/Matrix`, and the
  resulting bounds are mapped to normalized `/Rect`. The Form's own Matrix is
  applied exactly once by `Do`. Page rotation/crop boxes are retained, so normal
  rotated-page annotations need no extra rotation. NoRotate markup is supported
  by matching `Gfx::drawAnnot`'s inverse native page rotation about the annotation's
  top-left corner; this behavior is baked at export, not kept dynamic if a viewer
  later changes page rotation. Degenerate or non-finite geometry fails rather
  than disappearing.
- Original appearance resources, clipping, transparency groups, alpha and blend
  modes remain inside the Form. Annotation `/CA` is **not multiplied again**:
  Core-generated appearances already encode it, and Core draws existing AP as
  authoritative. This avoids squaring opacity. Arbitrary inconsistent third-party
  AP versus annotation metadata is not repaired.
- Missing normal AP can be generated by Core for FreeText, Line, Square/Circle,
  Polygon/PolyLine, Highlight/Underline/Squiggly/StrikeOut, Ink and Stamp. An
  OutputDev with no raster output composes CTM updates through `Gfx::drawForm`'s
  first BBox clip during `Annot::draw`, then freezes before AP-internal operators.
  This includes NoRotate compensation and preserves generated bounds extending
  beyond Rect (line endings, ink borders and callouts). Generation uses a private
  annotation dictionary with the current page's `/P` reference, including when
  the original omitted `/P`. The generated Form remains vector
  content. Existing AP is never regenerated. Text and Caret currently require an
  existing AP. Core font availability still controls generated FreeText glyphs.
- Page resources are copied from the effective inherited resource dictionary;
  the XObject subdictionary is copied separately, and new names avoid collisions.
  Original Contents references/bytes are retained between prefix `q` and suffix
  `Q`, with a separate `q`/`Q` per appearance. This isolates CTM, clipping, alpha
  and other graphics state for valid, balanced original content streams. Malformed
  original operators/graphics-state stacks are not repaired or fully validated.
- Core-generated nested direct memory streams are lifted into indirect objects
  before serialization. Existing indirect resource graphs are not duplicated.
  A complete rewrite retains catalog/page references, outlines, destinations,
  forms and links instead of reconstructing or rasterizing the document. It is
  not a sanitization/redaction operation: unreachable original objects may remain.

### Explicit safety limits

- Encrypted PDFs are rejected. All current xref objects and their direct children
  are scanned for `/ByteRange`, signature/timestamp dictionaries, and populated
  signature fields, rejecting signed input before mutation. This is conservative
  (even an unreachable signature dictionary is rejected), not cryptographic
  validation or historical-revision forensics. Empty unsigned signature fields
  remain widgets; changing a signed PDF while preserving its signature is not
  offered. Nested/oversized preflight graphs fail closed.
- Visible NoZoom and ToggleNoView annotations are rejected: their
  dynamic view behavior is not equivalent to ordinary content. Visible optional
  content, replies, actions, external-data and structure-linked annotations are
  rejected rather than silently dropping those semantics. Unsupported types
  include attachments, Sound/Movie, Screen, RichMedia, 3D and Redact.
- A simple Popup UI container can be removed with its flattened parent only when
  both are indirect annotations on the same page, their references are reciprocal,
  and the Popup has no independent content/action/reply/optional-content/structure
  data. This exception applies to Popup containers even if their own flags hide
  them: they are not page appearances and are never painted. Other popups fail;
  paired popups of preserved parents are retained. Replies referencing removed
  parents fail, including otherwise-hidden replies. Flattening deliberately
  removes the flattened annotation's editable comment metadata from the page.
- Missing AP that Core cannot generate, malformed AP, and ambiguous state
  selection are reported with one-based page/annotation locations. No successful
  partial export is published. Result counts distinguish painted annotations,
  generated appearances, removed Popup containers, and retained annotations.
  An output that reopens is not a substitute for visual regression tests.

Recommended regressions include: state-selected AP, translated/rotated/skewed
Matrix and nonzero BBox origins; 90/180/270-degree pages; shared inherited
resources/name collisions; original CTM/clipping isolation; existing and
Core-generated translucent highlights/ink; missing-AP line endings/callouts;
custom vector/image Stamps and FreeText; retained links/widgets/hidden annotations;
reciprocal versus complex popups/replies; malformed/missing AP; signed/encrypted
input; pre-existing output/input aliases; and no output on any error.

## Maintenance Rules

- Use product-neutral file names, namespaces, targets, diagnostics, and tests.
- Keep consumer-side document models, undo/redo, UI, and save orchestration out
  of this repository.
- Rebase or merge upstream changes deliberately and revalidate every use of
  unstable Core APIs.
- Test page insertion, import, deletion, movement, reordering, forms, optional
  content, named objects, output intents, and annotation identity after changes
  to the serializer.
- Commit and publish this repository before updating a consuming repository's
  submodule gitlink.
